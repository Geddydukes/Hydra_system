# Hydra — RL Training Loop Specification

## 1. Overview

Hydra leverages its **symbolic teachers** not only for inference, but also as a **source of ground truth and reward signals** for post-training language models.

By collecting structured data from real queries, symbolic outputs, and explanation layers, Hydra can incrementally **fine-tune general LLMs** using reinforcement learning (RL), Direct Preference Optimization (DPO), or Supervised Fine-Tuning (SFT), depending on the task.

This enables the general LLM to:

- **Internalize symbolic behavior** over time,
- Provide better fallbacks when teachers don’t exist,
- Generate more faithful explanations,
- Gradually reduce reliance on expensive routing.

---

## 2. Training Objectives

| Objective                | Method    | Description                                                                                           |
| ------------------------ | --------- | ----------------------------------------------------------------------------------------------------- |
| **Faithful Explanation** | SFT / DPO | Teach the model to produce explanations that match symbolic traces                                    |
| **Correct Verdicts**     | DPO / RL  | Encourage model outputs that match teacher verdicts on structured inputs                              |
| **Symbolic Emulation**   | RL        | Shape model behavior on tasks covered by teachers                                                     |
| **Fallback Improvement** | RL        | Use symbolic outputs as reward signals to align model on unsupported tasks after teachers are created |
| **Long-Tail Expansion**  | SFT       | Learn from new teacher creation events to reduce routing misses                                       |

## 3. Data Generation Pipeline

Every Hydra inference produces a **structured log** suitable for training:

```json
{
  "input_text": "Does this loan meet DSCR policy?",
  "normalized_inputs": {"noi": 120000,"annual_debt_service": 100000},
  "teacher_id": "loan_dscr_v1",
  "teacher_version": "1.0.0",
  "symbolic_output": {
    "verdict": "FAIL",
    "outputs": {"dscr": 1.14},
    "trace": [...]
  },
  "llm_output": "It seems this loan does not meet the DSCR requirement of 1.20.",
  "explanation_output": "This loan fails because the DSCR of 1.14 is below 1.20.",
  "label_type": "positive",
  "approved_for_training": true
}
These are stored in a training tuples repository with versioned teacher references.

4. Tuple Types
Tuple Type	Source	Usage
Symbolic-Explanation	Router + Teacher + Explanation layer	Used for explanation SFT / DPO
Symbolic-Verdict	Teacher verdict vs. LLM prediction	Used for DPO / RL
Creation Event	SELLM outputs after approval	Used to train model on new tasks
Counterfactual	Auto-generated by teacher tests	Used to teach models to handle near-boundary conditions
Patch Event	Auto-update pipeline	Teaches model about regulatory changes

5. Training Methods
5.1 Supervised Fine-Tuning (SFT)
Used for explanation generation and structured completion.

Targets: explanation_output, verdict classification.

Pros: stable, low variance, good for early-stage alignment.

5.2 Direct Preference Optimization (DPO)
Pairs symbolic outputs vs. unaligned LLM outputs, preferring symbolic truth.

Example: choose between two LLM completions, reward the one that matches teacher verdict.

Pros: no need for reward model, stable.

5.3 Reinforcement Learning (PPO / GRPO)
Used for symbolic emulation and fallback tasks.

Reward signals:

+1 if verdict matches teacher

shaped rewards for partially matching traces/explanations

penalty for hallucinations or threshold errors

Can run in offline mode (on logs) or online with shadow routing.

6. Reward Signal Design
Signal	Source	Description
Verdict Match	Teacher verdict	Binary reward for exact match
Trace Fidelity	Teacher trace	Reward based on how closely LLM explanation references correct rules and thresholds
Counterfactual Sensitivity	Counterfactual tests	Reward if model correctly flips answer under minimal perturbation
Format Compliance	Schema validator	Reward for structured outputs in correct format
Source Attribution	Teacher metadata	Bonus for citing correct rule IDs or citations in explanations

7. Offline vs Online Loops
7.1 Offline Loop
Periodically sample logs from training tuple repository.

Filter for approved_for_training = true.

Run SFT → DPO → RL sequentially (or selected subset).

Evaluate on held-out counterfactual + regression sets.

Publish new model snapshot.

7.2 Online Loop (Shadow Mode)
Run new model in parallel with teachers on live traffic.

Compare outputs to teacher verdicts and explanations.

Use differences as online rewards to update policy in real time.

Promote online model when performance exceeds threshold.

8. Evaluation Metrics
Metric	Description
Verdict Accuracy	% of model verdicts matching symbolic teachers
Explanation Fidelity	BLEU / ROUGE / rule-ID matching between explanation and trace
Counterfactual Sensitivity	% of counterfactual cases correctly flipped
Drift Detection	KL divergence between teacher verdict distribution and model outputs over time
Shadow Accuracy	Performance gap between shadow model and teacher routing

9. Versioning & Safety
Training tuples are versioned with teacher_id@version to ensure consistency.

Old training data is not retroactively relabeled when teachers change — instead, new versions generate new tuples.

Models trained on tuples are snapshot versioned and evaluated before deployment.

Drift detectors monitor for model vs teacher divergence post-deployment.

11. Incremental Post-Training Strategy
Hydra’s RL loop is designed for incremental, domain-focused alignment rather than monolithic retrains:

Per-domain batches — e.g., retrain only underwriting explanations if new DSCR rules emerge.

Counterfactual-heavy evaluation for stability.

Symbolic supervision acts as a stabilizer, reducing catastrophic forgetting.

12. Strategic Benefits
Converts symbolic correctness into LLM competence over time.

Reduces routing load by teaching the model to handle previously symbolic-only tasks.

Produces regulation-aligned models with transparent ground truth.

Makes Hydra’s knowledge base self-reinforcing — new teachers → new training data → smarter LLM.
```
